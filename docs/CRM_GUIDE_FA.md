# راهنمای CRM — فرصت فروش و باشگاه مشتریان

> این سند برای کسی است که با سیستم کار می‌کند، نه برای توسعه‌دهنده.

---

## بخش ۱ — فرصت فروش

### تفاوت لید و فرصت

| | لید | فرصت |
|---|---|---|
| چیست | کسی که دارید صلاحیتش را می‌سنجید | معامله‌ای که رویش کار می‌کنید |
| چند تا؟ | یک نفر = یک لید | **یک مشتری = چند فرصت هم‌زمان** |
| مثال | «شرکت الف تماس گرفت» | «پروژهٔ شبکهٔ الف» + «قرارداد پشتیبانی الف» |

اگر مشتری واحدی هم‌زمان دو معامله دارد، باید **دو فرصت** بسازید، نه یک لید با
مبلغ جمع‌شده. وگرنه وقتی یکی برنده و دیگری بازنده شود، هیچ عددی درست نمی‌ماند.

### مراحل

شناسایی ← واجد شرایط ← پیشنهاد ← مذاکره ← برد / باخت

حرکت به عقب مجاز است (معامله‌ای که ساکت شده، به «واجد شرایط» برمی‌گردد). ابزاری
که این را ممنوع کند، فقط دور زده می‌شود.

### ارزش وزنی — مهم‌ترین عدد این صفحه

```
ارزش وزنی = مبلغ × احتمال
```

چرا مهم است: جمع خام فرصت‌های باز همیشه پیش‌بینی را **خوش‌بینانه** می‌کند، چون
معامله‌ای با ۱۰٪ احتمال را مثل معامله‌ای امضاشده می‌شمارد. ارزش وزنی عددی است
که می‌توانید به آن تعهد بدهید.

مثال: ۴ میلیون با احتمال ۷۵٪ + ۱ میلیون با احتمال ۵۰٪
→ خط لوله ۵ میلیون، ولی **ارزش وزنی ۳٫۵ میلیون**.

هر مرحله احتمال پیش‌فرض دارد (شناسایی ۱۰٪ … مذاکره ۷۵٪) ولی می‌توانید تغییرش
دهید — شما معامله را بهتر از یک جدول می‌شناسید.

### دلیل باخت — الزامی است

وقتی فرصتی را «باخت» می‌کنید، سیستم دلیل می‌خواهد. این آزاردهنده به‌نظر می‌رسد
ولی تنها راهی است که بعداً بتوان به «چرا معاملات را می‌بازیم؟» پاسخ داد. دلایل
از فهرست انتخاب می‌شوند (نه متن آزاد) وگرنه قابل جمع‌بندی نیستند.

فهرست دلایل در جدول `crm_loss_reasons` قابل ویرایش است.

### تبدیل به سند فروش

فرصت برنده → دکمهٔ «تبدیل به سند» → پیش‌فاکتور یا فاکتور.

- اگر برای فرصت **اقلام پیشنهادی** ثبت کرده باشید، همان‌ها سطرهای سند می‌شوند.
- اگر نه، یک سطر با عنوان و مبلغ فرصت ساخته می‌شود.
- سند **پیش‌نویس** ساخته می‌شود. ثبت در دفتر کل همچنان با تأیید فاکتور در بخش
  فروش انجام می‌شود — یعنی دقیقاً یک مسیر به حسابداری وجود دارد.
- تبدیل دوباره سند تکراری نمی‌سازد؛ همان سند قبلی را نشان می‌دهد.

## بخش ۲ — باشگاه مشتریان

### 🔴 نکته‌ای که قبل از هر کاری باید بدانید

**امتیاز یک بدهی مالی است، نه یک عدد تزئینی.**

هر امتیازی که می‌دهید، تخفیفی است که بدهکار می‌شوید. صفحهٔ باشگاه به همین دلیل
«بدهی باز» را به‌عنوان یکی از چهار عدد اصلی نشان می‌دهد:

```
بدهی باز = امتیاز در گردش × نرخ تبدیل
```

قبل از تعیین نرخ کسب، این عدد را برای حجم فروش ماهانه‌تان حساب کنید.

### تعریف برنامه

`/admin/crm/loyalty` ← تب «برنامه» ← «ساخت برنامه»

| فیلد | معنی | مثال |
|---|---|---|
| نرخ کسب | امتیاز به‌ازای هر ۱ ریال فاکتور | `0.001` → فاکتور ۲ میلیونی = ۲۰۰۰ امتیاز |
| نرخ تبدیل | ارزش هر امتیاز | `10` → ۲۰۰۰ امتیاز = ۲۰٬۰۰۰ ریال |
| انقضای امتیاز | بعد از چند روز باطل شود | خالی = بدون انقضا |

در مثال بالا، هر فاکتور حدود **۱٪ تخفیف آینده** ایجاد می‌کند
(۰٫۰۰۱ × ۱۰ = ۰٫۰۱). این را عمداً حساب کنید.

### سطوح

تب «سطوح»: برای هر سطح یک **آستانهٔ امتیاز** و **درصد تخفیف** تعریف کنید.
مشتری خودکار در بالاترین سطحی قرار می‌گیرد که آستانه‌اش را رد کرده.

نمونه: برنز ۰ · نقره ۱۰۰۰ · طلا ۵۰۰۰

### امتیاز چطور جابه‌جا می‌شود

| رویداد | اثر |
|---|---|
| تأیید فاکتور | امتیاز **کسب** می‌شود |
| فاکتور پیش‌نویس | **هیچ امتیازی** — برای فروشی که هنوز قطعی نیست بدهی ایجاد نمی‌شود |
| مصرف امتیاز | امتیاز کم، تخفیف داده می‌شود |
| **برگشت فاکتور** | امتیاز همان فاکتور **معکوس** می‌شود |
| انقضا | با اجرای «انقضای امتیاز» ثبت می‌شود |
| اصلاح دستی | حرکت «اصلاح» در دفتر |

🔴 **موجودی هرگز مستقیم نوشته نمی‌شود.** هر تغییر یک سطر در دفتر امتیاز است، با
ارجاع به سند مبدأ. برای همین همیشه می‌توان پرسید «این امتیازها از کجا آمده؟» و
پاسخ گرفت.

**اگر موجودی منفی شد:** یعنی مشتری امتیازی را خرج کرده که بعداً فاکتورش برگشت
خورده. سیستم عمداً آن را منفی نشان می‌دهد و صفر نمی‌کند — این یک بدهی واقعی است
که باید دربارهٔ آن تصمیم بگیرید (بخشش با «اصلاح» یا کسر از فاکتور بعدی).

### کوپن تخفیف

تب «کوپن‌ها». همهٔ محدودیت‌ها **سمت سرور** بررسی می‌شوند، پس دستکاری در مرورگر
بی‌اثر است:

- تاریخ اعتبار · حداقل مبلغ سفارش
- سقف کل استفاده · سقف استفادهٔ هر مشتری
- تخفیف هرگز از مبلغ سفارش بیشتر نمی‌شود (فروش نباید به پرداخت تبدیل شود)

اگر کوپنی رد شود، پیام می‌گوید **چرا** — نه فقط «نامعتبر».

### آنچه مشتری می‌بیند

پورتال مشتری (`/fa/portal`) ← تب «امتیازهای من»:
موجودی · ارزش ریالی · سطح فعلی · فاصله تا سطح بعد · **تاریخچهٔ کامل امتیاز**.

تاریخچه عمداً نمایش داده می‌شود: عددی که مشتری نتواند ردیابی کند، عددی است که به
آن اعتماد نمی‌کند — و اولین تیکت پشتیبانی همیشه «چرا این‌قدر امتیاز دارم؟» است.

### اثر حسابداری

پیش‌فرض **خاموش** است (`loyalty_gl_enabled = 0`). اگر می‌خواهید امتیاز در دفتر
کل ثبت شود، ابتدا با حسابدارتان دربارهٔ حساب‌ها تصمیم بگیرید
(پیشنهاد: هزینهٔ بازاریابی `6900` / تعهد امتیاز `2900`).

## بخش ۳ — هوش تجاری CRM

فعلاً **ساخته نشده**، عمداً.

امتیازدهی لید، پیش‌بینی ریزش و پیش‌بینی فروش برای کار کردن به دادهٔ واقعی نیاز
دارند: حداقل **۲۰ مشتری فعال**، **۳ ماه تاریخچه** و **۵۰ تراکنش**. مدلی که روی
پنج رکورد آموزش ببیند، عدد تولید می‌کند نه پیش‌بینی — و عددی که مدیر به آن
اعتماد کند ولی پایه نداشته باشد، از نبودش بدتر است.

برای بررسی اینکه آیا داده کافی شده:

```bash
cd /var/www/habibazar
npx tsx scripts/crm-data-gate.ts
```

وقتی سبز شد، این بخش قابل ساخت است.
