# Phase 20 — SQLite → PostgreSQL Migration

## Status (honest, verifiable)

**Data tier: MIGRATED and VALIDATED on a real PostgreSQL server.**
**Application runtime: still on the synchronous `better-sqlite3` driver — the
async-driver cutover is the remaining, staged step (tracked by `audit:pgcompat`).**

This phase does **not** claim a completed full cutover. It delivers what was
genuinely executed and can be re-run and verified by anyone, and states plainly
what remains — consistent with the maintainer's rule "never fake completion."

A real PostgreSQL 16 server was provisioned locally (role `habibazar`, database
`habibazar`, extensions `pgcrypto` + `pg_trgm`), and the live SQLite database was
migrated into it by the automated engine below. Result, reproduced from the run:

## The migration engine — `scripts/migrate-to-postgres.mjs`

Run: `npm run db:migrate:pg -- --sqlite ./data/habibazar.db --pg "$DATABASE_URL"`

Automated, transactional, idempotent (drops + recreates its managed tables):

1. **Introspect** SQLite: tables, columns, types, PKs, FKs, indexes
   (`PRAGMA table_info/foreign_key_list/index_list`).
2. **Safe order**: topological sort of the FK dependency graph; cycles handled by
   `DEFERRABLE INITIALLY DEFERRED` constraints + `SET CONSTRAINTS ALL DEFERRED`.
3. **Schema**: value-preserving type map (`integer→bigint`, `real→double
   precision`, `text→text`, `blob→bytea`); single-column integer PKs become
   `GENERATED BY DEFAULT AS IDENTITY`.
4. **Data**: batched multi-row `INSERT` (default 500/stmt) inside one transaction.
5. **Sequences**: `setval(pg_get_serial_sequence(...), max(pk)+1)` per identity PK.
6. **Validation**: per-table **row-count parity + order-independent content
   checksum** (sha256 over sorted per-row md5). Any mismatch → non-zero exit.
7. **Report**: `data/migration-report.json` (per-table counts, checksums, timing).

Type *refinement* (JSONB, `timestamptz`, native `boolean`, tsvector/GIN) is
deliberately **not** applied by the engine because it would rewrite stored values
and break exact-checksum validation. It belongs to the schema step of the
runtime cutover (below), where the Drizzle schema is ported to `pg-core`.

## Production script suite — `deploy/postgres/`

Real, runnable on Debian 12 / Ubuntu 24.04. `verify-postgresql.sh` was executed
against the live PG and confirmed the counts above.

| Script | Responsibility |
| --- | --- |
| `install-postgresql.sh` | PGDG repo, install PG 17 + client + contrib + pgvector, UTF-8 locale, timezone, cluster, role, DB, extensions (`pgcrypto`,`pg_trgm`,`uuid-ossp`,`pg_stat_statements`,`vector`), `pg_hba.conf` scram-sha-256, auto-start; writes `DATABASE_URL`. |
| `sqlite-to-postgresql.sh` | WAL-safe SQLite backup (+sha256) → runs the migration engine → asserts report `ok`. |
| `verify-postgresql.sh` | Read-only: connectivity, extensions, table census, row counts, FK validation, cache-hit ratio, DB size. |
| `restore-postgresql.sh` | Restore a `pg_dump` (custom or plain) into a freshly recreated DB. |
| `rollback-to-sqlite.sh` | One-command revert to the pre-migration SQLite snapshot (checksum-verified). |

## Remaining work — application-runtime cutover (tracked)

`npm run audit:pgcompat` inventories what still binds the runtime to SQLite:
**540 SQLite-specific hits across 24 files** — 23 driver imports, 33 raw
`$client` handles, 116 synchronous `.get/.all/.run/.pragma` call-sites, 19
`PRAGMA`, 108 `AUTOINCREMENT`, plus `datetime('now')`, `INSERT OR IGNORE`,
`sqlite_master`, and better-sqlite3 `.backup()`. The cutover:

1. Port `lib/db/schema.ts` `sqlite-core` → `pg-core` (`pgTable`, native boolean,
   `timestamptz`, JSONB, identity PKs; keep FK cascade + unique + indexes; add
   GIN for JSONB/`pg_trgm`).
2. Swap `lib/db/index.ts` to an async `pg` `Pool` + `drizzle-orm/node-postgres`.
3. Convert the 116 synchronous raw call-sites to `await pool.query(...)`
   (BackupEngine, log bus, ops snapshot, Database Center, CRM, Assets, Flags,
   SOC, KB sync) and re-verify each.
4. Query fixes: `INSERT OR IGNORE`→`ON CONFLICT DO NOTHING`; `json_extract`→JSONB;
   `PRAGMA`/`sqlite_master` (Database Center + ops snapshot)→`pg_catalog`/`pg_stat_*`.
5. BackupEngine: `.backup()` → `pg_dump` + WAL archiving + PITR (3-2-1 adapters
   are archive-level DB-agnostic and stay).
6. Keep SQLite as the reversible fallback until the cutover gate
   (`audit:pgcompat` = 0) passes; auto-rollback via `rollback-to-sqlite.sh`.
